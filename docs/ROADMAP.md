# 路线与阶段验收

路线围绕“可重复完成本人声线的内容生产”展开，不预设商业化目标。视频方向采用可替换的原创虚拟角色，首个为卡通小机器人 `studio-bot`；真人照片或短视频驱动路线已取消，不作为待补素材或开发阻塞。以下区分已实现能力和仍需验证的范围。

## 当前进度：0.3（含 0.2 基础能力）

- 本地配音工作台已完成，已有短稿与约一分钟连续讲解的真实生成记录。
- 声线档案/项目快照、发音词典/读法预览、持久批量队列、取消隔离与工程ZIP恢复已实现。
- 本地规则整理、建议对照、明确确认后采用、无后续修改时撤销，以及本机模型接口已实现。
- 字幕讲解 MP4 与完整 HyperFrames 工程导出已实现；已有真实横屏渲染、解码检查与API任务记录。
- 约63秒字幕竖屏成片已通过真实生产队列渲染与解码检查；此记录不包含虚拟角色。
- 0.3 新增本人声音配原创机器人：本地可编辑 SVG，音频能量驱动嘴部开合，配合眨眼和轻微动作；横竖屏短片已独立渲染并检查，85项自动检查通过；角色观感待用户观看确认。
- 实时对话、字级强制对齐、几分钟成片与长期负载尚未验收；能量驱动的嘴部动作不作为精细音素口型的证明。

## 第一阶段：本地配音工作台

完成 TXT / Markdown 导入、整稿分段、单段编辑与重生成、异步进度与取消、持久项目及音频版本、既有样音试听，以及 WAV、MP3、段级 SRT、工程 ZIP 导出。

完成条件：

- 从文案导入到成品导出形成完整流程，应用重启后项目与有效版本仍可读取。
- 单段修改能够只重做该段，旧结果与新文本的关系清楚；整稿结果采用正确段序和选定版本。
- 运行、失败及取消有实际状态依据，取消任务不再被误记为成功，原有有效结果得到保留。
- 导出文件能够读取，字幕时间轴与所用音频一致，工程包不夹带外部模型、录音、依赖或缓存。
- 记录机器流程检查结果；新文案的主观声线、发音与自然度明确标记为待用户试听。

目前可用既有环境与素材开始，不需要用户先补录音、提供形象或选择云服务。

## 第二阶段：稳定的声音生产基础

根据第一阶段实际使用反馈，完善较长文案、批量任务、异常恢复、声音资产登记、发音词典、停顿规则及更精细的字幕时间轴。建立具有代表性的试听文案，涵盖数字、日期、英文、专有名词和较长句段。

完成条件是返工更少、局部修改可复现、长稿质量与耗时有实际记录。更多录音属于可选改善材料；是否采用及是否改善效果需要对比试听，不能仅凭文件数量判断。

## 第三阶段：受控的文案辅助

当前已使用仅本机接口接入文案整理和模型改写建议，保留原文、差异展示、确认和撤销。改写结果不会自动替代原稿并直接进入配音生成。

轻量本机模型实测可能删除限制条件或改变语义；数字/缩写保护只覆盖部分风险，不能当作事实准确性保证。
因此 AI 建议限短稿试用并要求逐句核对。以后可在同一接口下更换更强的本机模型，仍保留审阅流程。

这一阶段不以“接入多少模型”为目标，而以实际减少编辑工作且不改变关键信息为验收依据。

## 第四阶段：本人声音与虚拟讲解员

当前已复用配音及时间轴生成横屏/竖屏字幕讲解工程；横屏短片和约63秒竖屏均已实渲染，几分钟成片待验收。

0.3 采用本地原创卡通小机器人作为首个可替换角色，复用已有本人配音，不需要照片或短视频。角色源文件与动作数据随视频工程保留：嘴部按音频能量开合，眨眼与轻动按工程时间轴呈现，不模仿本人的脸，也不宣称音素级口型。界面默认 `virtual_host`，纯字幕 `captions` 继续可选；旧 API 客户端省略 `layout` 时继续得到字幕模式。

完成条件：

- 两种模式均支持横屏与竖屏，任务、取消、版本校验和原音频保持一致。
- 说话与停顿时嘴部动作有可检查的音频依据，角色与字幕无明显溢出或遮挡。
- 导出的 HyperFrames 工程包含可编辑 SVG、动作数据和原配音，能够继续修改或替换角色。
- 保存实际渲染、解码与工程检查证据，并将角色观感和新文案听感分别交由用户确认。

每次修改配音都会使旧视频失效，需要重新导出。实时对话涉及新的交互、延迟和表现要求，属于独立的未验收范围。

## 暂缓的扩张

第一版不引入多租户、计费、声音市场、移动端、复杂插件平台或大量模型接入。先验证个人工作流是否稳定、可修改和可复用，再根据真实用途决定是否增加团队或对外服务能力。
