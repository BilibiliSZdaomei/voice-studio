# 架构约定

本文件描述声稿 0.2 的责任边界及 0.3 虚拟讲解员扩展。具体接口、存储字段和运行行为以实现及验证记录为准；新增角色能力的测试结果不从既有字幕视频记录推定。

## 运行结构

```text
浏览器：apps/web（原生 ES modules，无前端构建步骤）
    │ 本机 HTTP
    ▼
服务：apps/api/voice_studio（Python 标准库）
    ├─ 项目、版本、任务与导出管理
    ├─ 本地数据目录
    └─ worker / 引擎适配器
           ├─ 既有独立 Python 3.12 + sherpa-onnx 2.0.1 + ZipVoice 环境
           ├─ 既有模型、参考录音、参考文本：只引用
           ├─ ffmpeg：音频处理与 MP3 导出
           └─ 本机 HyperFrames：字幕或虚拟讲解员工程与 MP4
```

前端负责项目操作、段落编辑、任务状态和试听。API 负责校验请求、持久化、任务调度和受控文件访问。耗时推理通过 worker 调用既有独立环境，避免在 HTTP 请求生命周期内同步等待整稿生成，也避免将模型依赖强加给 API 环境。

服务默认绑定回环地址。每个数据根由操作系统文件锁独占，第二个服务不能同时对同一数据根恢复任务或写入项目。第一版按本机个人工作流设计，不默认暴露到局域网或公网；跨设备及多用户访问需要单独设计鉴权与资源隔离。

## 代码与数据分离

| 内容 | 位置或规则 |
| --- | --- |
| 应用代码与文档 | 从 GitHub 克隆的项目目录。 |
| 项目数据根 | 由本机配置中的 `data_root` 指定，独立于源码和同步目录。 |
| 项目、任务、音频、导出、缓存 | 置于配置的数据根目录内，不写入代码目录，不进入 Git。 |
| 既有模型、录音和环境 | 使用配置记录的绝对路径引用，不移动，不为本项目复制一份。 |

数据根应可配置。工程 ZIP 不应隐含收集数据根之外的文件，也不应为追求“可复用”而把大型模型与运行环境复制进每个项目。迁移机器时需重新绑定外部资源；工程包应说明这些外部依赖。

## 核心对象与一致性

- **项目**：文案、段落顺序、声音配置、创建与修改信息。
- **段落**：稳定标识、当前文本、顺序以及选中的音频版本。
- **音频版本**：输入文本快照、引擎与参数、声音配置、输出文件和实际时长。
- **任务**：目标项目与段落、状态、阶段、完成数量、错误以及取消请求。
- **导出**：所选音频版本、段序及必要的拼接设置，形成可追溯的成品快照。
- **视频表现配置（0.3）**：`layout` 选择 `virtual_host` 或 `captions`；`avatar_id` 标识可替换角色，首个为 `studio-bot`。角色配置不改变声音快照或配音版本。

文本改变即使旧音频失效，不能靠“文件仍存在”判断当前段落已完成。正在运行的任务应绑定提交时的输入快照；生成期间的后续编辑不得被旧任务结果覆盖。重生成应保留历史版本关系，不覆盖唯一成品。持久化应避免半写文件；服务异常退出后，不应将遗留运行状态无限显示为运行中。

## 异步任务与取消

任务至少区分排队、运行、成功、失败及取消。可另设取消中状态；界面应展示真实状态，不使用无依据的百分比或预计剩余时间。

整稿任务按段执行并记录完成情况。取消应阻止后续段落启动，并处理当前 worker 或其子进程；是否完成取消以实际执行状态为准。已完成版本可保留，但部分写入的文件不能被登记为有效成品。取消或失败不能破坏此前已验收的音频版本。

## 引擎适配与资源

引擎接口应接受文本、声音资源引用、生成设置和指定输出位置，返回文件、实际时长及必要元数据。项目管理不应依赖某个模型命令行的细节。第一版只需实现既有 ZipVoice 路径；其他引擎作为后续适配，不预建无实际调用的复杂插件体系。

声音档案引用模型、参考录音及参考文本。项目冻结声线与词典快照，同时保存原稿与实际读法，便于定位输入变化。

## 导出与时间轴

整稿 WAV、MP3 与段级 SRT 必须使用相同的段落顺序和音频版本。SRT 根据实际段时长及拼接间隔计算累计时间；若配音或拼接设置变化，相关字幕与成品须重新生成或标记失效。基础段级时间轴不宣称达到词级或字级对齐精度。

工程 ZIP 保存可审阅的项目数据、版本信息与选定成品。默认排除模型、参考录音、依赖环境、缓存和临时文件。导出时检查段落完整性；对于缺失或过期音频应给出明确状态，不能静默跳过。

## 可扩展边界

声音资产、发音词典、有保护的文案改写和视频表现分别复用项目与版本。改写需要保留原文、展示差异、经用户确认后再采用；远程服务必须主动启用。视频消费带版本的配音导出及其时间轴，声音听感验收单独记录，视觉制作不重新触发语音推理。字级强制对齐和实时对话仍属独立的未验收范围。

## 0.2 模块

- `assets.py` 保存声线引用与发音词典，原子写入和版本冲突保护；参考音 SHA256 用于检测外部修改。
- `production.py` 负责项目快照、词典主动应用、批量校验、建议稿审阅/采用/撤销和工程恢复编排。
- `job_queue.py` 串行处理持久的语音与视频任务，区分取消当前任务与取消排队任务。
- `archive.py` 先验证 ZIP 目录、容量、PCM 和文案/时间轴一致性，再暂存并原子注册新项目。
- `prepare.py` 提供保留事实的规则整理和本机模型适配，禁止重定向，不自动采用模型输出。
- `video.py` 使用已导出 WAV 与段级时间轴生成本地 HyperFrames 工程，并实际渲染、探测 MP4。
- `apps/web/production.js` 将新增生产工具拆到独立 UI 模块，复用主工作台的版本与错误处理。

## 0.3 虚拟讲解员

`avatar.py` 负责原创机器人角色资源及从导出 WAV 提取音频能量，视频模板负责按工程时间驱动 SVG 嘴部、眨眼和轻微动作。角色来自本地可编辑 SVG，不读取真人照片或短视频，不仿制本人的脸；未来更换角色沿用相同的视频输入和动作约定，不增加底层声音引擎依赖。

`audio_envelope(wav_path, sample_hz=15)` 返回采样频率、时长和归一化能量 `levels`；`build_host_composition(duration, aspect, envelope, avatar_id="studio-bot")` 将数据写入 `templates/virtual-host.html` 模板，生成 `compositions/host.html`，子工程标识为 `voice-host`。SVG 与动作参数内联于该文件，能量采样另存为 `audio-envelope.json`，两者均随工程 ZIP 保留并可编辑。

嘴部开合是音频能量的视觉表达，不包含音素识别、精细口型对齐或情绪识别。动作应随工程时间确定，支持渲染跳转和重放；静音不得通过循环说话动画填充。导出沿用完整原 WAV、原生分段音频和真实段间静音，不能为了动作重排或裁剪配音。

`VideoExporter` 根据 `layout` 选择字幕模板或虚拟讲解员模板，在新的视频 UUID 目录内生成角色、动作数据和工程。工程 ZIP 包含本次使用的内联角色源文件及能量采样；参考录音、模型、依赖缓存继续排除。源音频版本、WAV SHA-256、布局和角色标识进入视频元数据，便于追溯。虚拟讲解员的结果标记 `animation="audio_energy_driven"`，元数据标记 `mouth_sync="amplitude_not_phonemes"`。

界面默认选择 `virtual_host` 并提交 `avatar_id="studio-bot"`；API 省略 `layout` 时按 `captions` 处理以兼容旧客户端。布局与角色选项必须校验，未知值不能静默替换成另一种已完成效果。渲染与测试结果见验证记录，尚未完成的能力不能仅凭模板存在标记为可用。
